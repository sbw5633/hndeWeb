# R2 / 비밀키 관리 — 무엇을 어디에 두는지

**현재 Flutter Web은 R2 키를 갖지 않고, Cloudflare Worker만 R2에 붙습니다.**  
Worker 설치·`env.worker`·로컬/배포 URL은 **`docs/CLOUDFLARE_WORKER_설정.md`** 를 따릅니다.

이 문서는 **원칙**과 **Firebase(DB)와의 관계**를 정리합니다.

---

## 1. 먼저 오해 풀기

| 질문 | 답 |
|------|-----|
| **Firebase DB(Firestore)에 R2 Access/Secret 키를 저장해 두고 앱에서 읽어 쓰라는 거냐?** | **아니요.** 일반적으로 그렇게 하면 안 됩니다. 앱(웹)이 Firestore에서 그 값을 읽을 수 있게 두면, 결국 **브라우저/앱 사용자 쪽으로 비밀키가 나가게 됩니다.** |
| **그럼 Firestore는 뭐에 쓰나?** | **파일 URL, 업로드 이력, 제목, 사용자 uid** 같은 **비밀이 아닌 데이터**만 저장합니다. 이미 이 프로젝트도 그렇게 쓰고 있습니다. |
| **R2 비밀키는 어디에 두는 게 맞나?** | **서버(백엔드)만** 가져야 합니다. 예: **Firebase Cloud Functions 환경 변수 / Secret**, **Cloudflare Workers Secret**, 자체 API 서버 환경 변수. |

---

## 2. 지금 이 Flutter Web 프로젝트가 쓰는 방식 (`env.worker` + Worker URL)

### 무엇을 하는지

- `env.worker`에 **`R2_WORKER_URL_PROD`** 만 두면 **디버그·릴리즈 모두** 같은 배포 Worker를 씁니다.
- **R2 Access/Secret 키는 Flutter 번들에 없습니다.** Worker가 R2 **바인딩**으로 접근합니다.
- **Git에는 `env.worker`를 올리지 않음** (`.gitignore`).

### 한계 (반드시 알 것)

- Worker URL은 공개되므로, **Worker 쪽에서** Firebase 토큰 검증·관리자 uid·다운로드 서명 등으로 보호합니다.
- 자세한 설정은 **`docs/CLOUDFLARE_WORKER_설정.md`** 참고.

---

## 3. “제대로” 관리하는 방법 (프로덕션 권장)

### 원칙

1. **R2 Access Key / Secret Key** → **클라이언트(Flutter Web)에는 절대 넣지 않는다.**
2. **Firebase Auth**로 “이 사용자가 업로드/다운로드 해도 되는지”만 검증한다.
3. 실제 R2 작업(업로드, presigned URL 발급, 삭제)은 **서버**가 한다.

### 서버 예시

| 방식 | 비밀키 보관 위치 |
|------|------------------|
| Firebase Cloud Functions | `firebase functions:secrets:set` 또는 함수 전용 환경 변수 |
| Cloudflare Worker | Worker **Secrets** |
| 자체 Node/Go 서버 | 서버 OS 또는 배포 플랫폼의 환경 변수 |

### 클라이언트(Flutter Web)가 하는 일

- 로그인 후 **Callable Function** 또는 **HTTPS API**를 호출한다.
- 예: `getUploadUrl()`, `confirmUpload()`, `getDownloadUrl(fileId)`  
- 서버가 R2에만 접근하고, 클라이언트에는 **짧게 쓰는 URL** 또는 **일회성 업로드 URL**만 준다.

### Firestore 역할 (이때)

- **파일 메타데이터** 저장: `fileId`, `storagePath`, `uploaderUid`, `createdAt` 등.
- **R2 시크릿 키 문자열**은 저장하지 않거나, 저장하더라도 **클라이언트가 읽을 수 없는 규칙 + 서버 전용**이어야 하며, 보통은 **그냥 서버 환경 변수만** 씁니다.

## 4. 실무에서의 단계별 정리

### 로컬에서 개발할 때 (지금 구조)

1. `env.worker`에 **`R2_WORKER_URL_PROD`** 만 채움 (배포된 Worker URL).
2. 실행: `.\run_web.ps1` 또는 **Flutter Web (Chrome, env.worker)** — 디버그도 실서버 Worker 사용.
3. 배포 빌드: `.\build_web.ps1` — 동일하게 PROD URL.
4. Worker 코드만 로컬에서 뜨워 볼 때는 `docs/CLOUDFLARE_WORKER_설정.md` 의 **로컬 Worker(선택)** 절과 `WORKER_MODE=local` 참고.

### CI(GitHub Actions 등)에서 빌드할 때

- 저장소에는 키를 넣지 않는다.
- CI **Secrets**에 `R2_*` 값을 넣고, 빌드 스크립트에서 `--dart-define` 또는 `--dart-define-from-file`을 **CI가 생성한 파일**로 넘긴다.
- (여전히 웹 번들에 들어가므로, 공개 배포면 3절 구조로 전환하는 게 안전하다.)

### 공개 웹 서비스로 갈 때

- **목표:** 브라우저 번들에 R2 시크릿이 **아예 없게** 만든다.
- **방법:** Cloud Functions / Worker 등에 R2 키를 두고, Flutter는 API만 호출.

---

## 5. 한 줄 요약

- **Firestore에 R2 시크릿을 넣어서 앱이 읽게 하라는 뜻이 아닙니다.**
- **지금:** R2 키는 **Cloudflare Worker**에만 있고, Flutter에는 **Worker 공개 URL만** (`env.worker`, Git에 안 올림).
- **운영:** Worker의 `ADMIN_UIDS`, `DOWNLOAD_SIGN_SECRET`, R2 바인딩으로 접근 통제.

이 파일은 프로젝트 루트 `docs/R2_비밀키_관리_안내.md`에 있습니다.

---

## 6. Firebase Functions 말고, 비용·남용 걱정할 때

### Firebase Functions가 “무조건 유료”는 아님

- **Blaze(종량제)** 플랜이어도 **무료 할당량**이 있고, 소규모·내부용이면 월 비용이 거의 안 나오는 경우가 많다.
- 다만 **카드 등록·과금 구조**가 부담이면 다른 경로를 쓰면 된다.

### R2 쓰는 입장에서 무난한 대안: **Cloudflare Workers**

- 이미 **R2가 Cloudflare**이므로, **같은 계정에서 Worker**로 “presigned URL 발급 / 업로드 프록시”만 두는 패턴이 흔하다.
- Workers **무료 플랜**에도 일일 요청 한도가 있어, **API 키만 받아오는 수준**의 트래픽이면 대부분 무료 안에서 동작한다(정확한 한도는 Cloudflare 요금 페이지 기준).
- **R2 시크릿은 Worker Secrets**에만 두고, 웹은 **Worker HTTPS URL**만 호출 → Flutter 번들에 R2 키 없음.

### “비정상 접속으로 요금 폭탄” 줄이는 공통 방법

| 수단 | 설명 |
|------|------|
| **권한 최소 R2 API 토큰** | 해당 버킷·읽기/쓰기만 허용. 서버(Worker)에만 붙인다. |
| **레이트 리밋** | Cloudflare **Rate limiting / WAF** 규칙, Worker 안에서 IP·uid당 호출 제한. |
| **인증** | Firebase Auth 등으로 “로그인한 사용자만” Worker에 요청 허용(토큰 검증은 Worker 또는 별도 검증 로직). |
| **과금 알림·상한** | Cloudflare·결제 수단에 **알림·예산** 설정. R2/Workers 대시보드에서 사용량 모니터링. |
| **presigned URL 짧은 만료** | 업로드·다운로드 URL 유효시간을 짧게(예: 수 분) 두어 URL 유출 피해 축소. |

### 정리

- **Functions 대신** → 같은 생태계면 **Cloudflare Workers + R2** 조합이 비용·구성 모두 무난한 편이다.
- **요금 폭탄**은 “무료냐 유료냐”보다 **남용 방지(레이트 리밋·최소 권한·짧은 presigned)** 와 **대시보드 알림**으로 줄이는 게 실무적으로 중요하다.
